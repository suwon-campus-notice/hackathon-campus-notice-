# Coetus 화면 명세 (프런트엔드 기준)

백엔드와 DB 설계의 기준이 되도록, 프런트엔드가 만든 화면과 각 화면이 필요로 하는 데이터·권한·규칙을 정리합니다. 구현은 `frontend/`에 있으며, 데이터는 아직 백엔드 없이 `frontend/src/store/`의 임시 저장소와 `frontend/src/mocks/seed.ts` 예시 데이터를 사용합니다. API가 정해지면 `store`의 액션을 API 호출로 바꾸고 화면 코드는 유지합니다.

> 이 문서는 팀 회의에서 정한 내용과 프런트엔드 구현 중 가정한 내용을 함께 담고 있습니다. **"(가정)"** 표시가 있는 항목은 정해진 적이 없어 임시로 정한 것이므로 팀에서 확인이 필요합니다.

## 1. 화면 이동 구조

로그인 후 첫 화면은 **내 팀 목록**입니다. 팀을 고르면 그 팀 안의 메뉴로 바뀝니다.

```text
로그인 → 내 팀 목록 ─┬─ [팀 안] 홈 / 일정 / 할 일 / 멤버
                      ├─ 시간표 (개인 하나, 모든 팀이 공유 — 가정)
                      └─ 내 정보
```

| 메뉴 | 하단 탭 |
| --- | --- |
| 팀 밖 | 팀 / 시간표 / 내 정보 |
| 팀 안 | 홈 / 일정 / 할 일 / 멤버 |

## 3. 핵심 규칙

### 3.1 계정

- 자체 아이디·비밀번호로 가입하고 이름과 학번을 입력합니다. 재학생 인증은 하지 않습니다.
- 아이디는 중복될 수 없습니다. 가입 화면의 "중복 확인" 버튼으로 확인하며, 가입 시점에 서버가 한 번 더 확인해야 합니다.
- 비밀번호 찾기는 이메일 없이 **질문과 답**으로 합니다. 가입할 때 질문 10개 중 하나를 고르고 답을 입력합니다.
  - 답을 틀릴 수 있는 횟수는 5회입니다. 5회를 넘으면 잠시 막습니다. 막는 시간은 정해지지 않았습니다.
  - 답은 암호화(해시)해서 저장하고, 비교할 때 띄어쓰기와 대소문자를 무시합니다. (가정)
- 아이디 찾기는 가입할 때 입력한 이름과 학번이 일치하는 계정의 아이디를 보여줍니다. (가정)
- 화면에서 사람은 이름으로 표시합니다. (임시, 팀 회의 예정)

### 3.2 팀

- 한 사람이 여러 팀에 속할 수 있습니다.
- 팀을 만든 사람이 팀장이 됩니다. 팀장은 다른 팀원에게 넘길 수 있고, 팀원은 탈퇴할 수 있습니다.
- 팀장이 팀원을 내보내는 기능은 없습니다.
- 팀장은 팀장을 먼저 넘긴 뒤에 탈퇴할 수 있습니다. (가정)
- 초대 링크는 7일 뒤 만료됩니다. 만료 후에는 새 링크를 만들어야 합니다. 새 링크를 만들면 기존 링크가 어떻게 되는지는 정해지지 않았습니다.
- 팀을 만들 때는 팀 이름만 입력합니다.

### 3.3 시간표와 공통 가능 시간

- 시간표는 **바쁜 시간만** 입력합니다(수업, 알바 등). 나머지는 가능한 시간으로 계산합니다. 수업명은 입력받지 않습니다.
- 입력 항목: 요일(월~일), 시작 시간, 종료 시간, 구분(수업 / 활동 불가). 시간은 30분 단위입니다.
- 입력 방식은 두 가지입니다: 표에서 칸을 눌러 선택, 직접 입력(요일·시작·종료·구분 선택).
- 기본 화면은 21시까지 보이고, 이후 시간대에 일정을 입력하면 24시까지 칸이 늘어납니다.
- 같은 요일에 겹치는 일정, 종료가 시작보다 빠른 일정은 입력할 수 없습니다.
- 공통 가능 시간 계산 범위는 09:00~21:00입니다. 요일마다 **전원이 가능한 시간이 있으면 그 시간만**, 없으면 **그날 가장 많은 인원이 가능한 시간만** 보여줍니다.
- 시간표를 입력하지 않은 팀원이 있으면 **입력한 사람 기준**으로 계산하고, 아직 입력하지 않은 팀원 이름을 안내합니다. 이때 "전원"은 입력한 팀원 전원을 뜻합니다.
- 추천 시간은 인원이 많은 순, 같으면 긴 순으로 최대 3개이며 1시간 이상인 구간만 포함합니다.
- 계산 로직: `frontend/src/lib/availability.ts` (테스트 포함). 백엔드가 서버에서 계산한다면 같은 규칙을 따라야 합니다.

### 3.4 회의 시간 투표

- 투표는 팀원 누구나 만들 수 있습니다. 한 번에 하나만 진행할 수 있습니다.
- 후보는 공통 가능 시간의 추천 시간에서 만들어집니다. 회의는 **시작 시간만** 정합니다(회의 길이는 서비스 영역 밖).
- 복수 투표입니다. 투표 전에도 다른 팀원의 득표 현황이 보이고, 투표 후에는 내가 고른 항목이 색으로 구분되며 "수정"으로 고칠 수 있습니다.
- 투표 기한은 24시간입니다.
- **과반수**: 전체 팀원 기준입니다(4명이면 3명 이상). 계산식은 `floor(팀원 수 / 2) + 1`입니다.
- 과반을 넘은 후보가 여럿이면 **표가 가장 많은 후보**로 자동 확정합니다.
- 최다표 후보가 둘 이상이면 **그 후보들끼리 재투표**합니다(득표는 초기화). 재투표에서도 동률이면 어떻게 할지는 정해지지 않았습니다.
- 24시간 안에 과반이 안 나오면 투표가 마감됩니다. 이후 **팀장이 단독 최다표 후보로 확정**하거나 **다시 투표**를 시작합니다. (가정) 마감 시점의 최다표가 동률이면 확정은 할 수 없고 다시 투표만 가능합니다.
- 진행 중인 투표는 만든 사람이나 팀장이 취소할 수 있습니다. 취소하면 받은 표가 모두 사라집니다. (가정)
- 확정된 회의 시간은 **팀장만** 변경할 수 있습니다. 변경 시 팀원 알림이나 재투표 여부는 정해지지 않았습니다.
- 판정 로직: `frontend/src/lib/vote.ts` (테스트 포함).

### 3.5 목표와 할 일

- 흐름: 팀장이 큰 목표와 개인별 목표(할 일)를 작성 → 팀원이 수행 → 팀장이 확인.
- 상태는 **진행 중 → 완료 요청 → 확인 완료** 세 가지입니다. 할 일은 만들어지면 "진행 중"으로 시작합니다.
- 항목: 제목, 담당자, 마감일, 상태. 담당자와 마감일은 팀장이 정합니다.
- 담당자는 GitHub PR 설명처럼 **수행한 작업과 결과를 적는 칸(수행 내용)**을 작성합니다. 확인 완료 후에도 수정할 수 있습니다.
- 반려(사유 작성) 기능은 없습니다.
- 팀장의 할 일은 팀장이 직접 확인합니다.
- 목표와 할 일은 수정·삭제할 수 있습니다. 목표를 삭제하면 안의 개인 목표도 함께 삭제됩니다. (가정)
- **공개 범위**: 할 일은 담당자 본인과 팀장만 볼 수 있습니다. 팀원은 자기 할 일만 보고, 팀장은 팀의 모든 할 일을 봅니다. 따라서 팀원에게는 팀 전체 진행률을 보여주지 않습니다.

## 4. 데이터 모델 (프런트엔드가 가정한 형태)

`frontend/src/types.ts`가 기준입니다. DB 설계 시 참고하세요.

| 개체 | 주요 필드 |
| --- | --- |
| User | id, 이름, 아이디, 학번 (+ 비밀번호 해시, 찾기 질문 번호, 답 해시) |
| Team | id, 이름, 팀장 id, 팀원 id 목록, 초대 코드, 초대 만료일 |
| TimetableEntry | id, 사용자 id, 요일(0=월~6=일), 시작, 종료(시 단위, 9.5=9시 30분), 구분(수업/활동 불가) |
| Vote | id, 팀 id, 만든 사람, 후보(요일+시작 시각) 목록, 표(사용자 id → 후보 id 목록), 마감 시각, 재투표 여부, 마감 여부 |
| Meeting | 팀 id, 요일, 시작 시각, 득표 수 |
| Goal | id, 팀 id, 제목 |
| Todo | id, 목표 id, 팀 id, 제목, 담당자 id, 마감일, 상태, 수행 내용 |

## 5. 아직 정해지지 않은 것

회의에서 정해야 하는 항목입니다.

- 시간표가 개인 하나인지, 팀마다 따로인지 (현재는 개인 하나)
- 동률 재투표에서도 동률이 나올 때의 처리
- 마감 후 최다표가 동률일 때의 처리 (현재는 다시 투표만 가능)
- 새 초대 링크를 만들면 기존 링크가 즉시 무효가 되는지
- 팀장이 회의 시간을 바꿀 때 팀원에게 알림을 줄지
- 비밀번호 찾기 5회 초과 시 막는 시간, 아이디 찾기의 횟수 제한
- 비밀번호 규칙(길이 등), 아이디 규칙(길이, 문자)
- 팀 탈퇴 시 내가 한 투표와 맡은 할 일의 처리
- 확인 완료 후 수정할 때 팀장에게 다시 알릴지
- 알림 기능 전체 (현재 계획에 없음)
